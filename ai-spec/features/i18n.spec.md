## Architecture

### Context Layer

```
LanguageContext.js   → createContext()
useLanguage.jsx      → LanguageProvider (wraps App in App.jsx)
useLanguage.js       → useLanguage() hook (consumer)
```

### Provider (`LanguageProvider`)

Wraps the entire app in `App.jsx` (outside `MemoryRouter`).

**State:**
- `language` — current language code (string)
- Initialized from `localStorage.getItem('language')` or defaults to `'en'`

**Effects:**
- On language change: sets `document.documentElement.lang` attribute
- On language change: persists to `localStorage`

**Context value:**
```js
{ language, changeLanguage, t, localize, LANGUAGES }
```

### Translation Function: `t(key)`

Resolves dot-notation keys against `translations.json`:

```js
t('hero.greeting')
// → translations[language].hero.greeting
// → "Hi, I'm Coach E.T" (en)
```

**Fallback:** Returns the raw key string if the path is not found.

Memoized with `useCallback` (dependency: `language`).

### Localize Function: `localize(obj)`

Resolves multilingual data objects from JSON data files:

```js
localize(skill.name)
// skill.name = { en: "Frontend Development", fr: "Développement Frontend", vn: "Phát Triển Frontend" }
// → "Développement Frontend" (when language is 'fr')
```

**Fallback chain:** `obj[language]` → `obj.en` → `obj` (raw)
- If `obj` is a plain string, returns it as-is
- If `obj` is an array, returns it as-is
- If `obj` is `null`/`undefined`, returns `''`

Memoized with `useCallback` (dependency: `language`).

**Usage pattern:**
- `t()` is for UI chrome strings (keys in translations.json)
- `localize()` is for content data (multilingual objects in JSON data files)

## LanguageSwitcher Component

- **Position:** Fixed on screen (positioned via CSS `.language-toggle`)
- **Toggle button:** Shows current language code in uppercase (e.g., `EN`)
- **Dropdown menu:** `.language-menu` with `.active` class when open
- Each option shows `lang.code.toUpperCase()` + `lang.name`
- Active language has `.language-option.active` class
- **Outside click:** Closes menu via document click listener

## Multilingual Data Files

All four data files use multilingual objects for text fields:

### Pattern
```json
{
  "name": { "en": "Frontend Development", "fr": "Développement Frontend", "vn": "Phát Triển Frontend" },
  "level": { "en": "Advanced", "fr": "Avancé", "vn": "Nâng Cao" }
}
```

Non-text fields (id, emoji, image, link, category, width, tech arrays) remain plain values.

### skills.json (8 skills)
Multilingual fields: `name`, `level`, `details` (array)

### strengths.json (4 strengths)
Multilingual fields: `title`, `points` (array)

### projects.json (9 projects)
Multilingual fields: `title`, `description`, `modalData.problem`, `modalData.solution`, `modalData.lessons` (array)
Plain fields: `id`, `category`, `image`, `link`, `modalData.tech`

### resources.json (2 resources)
Multilingual fields: `description`
Plain fields: `title` (brand names stay English), `image`, `link`

## Validation Error Pattern

Contact form validators return translation **keys** (not strings):

```js
function validateName(val) {
  if (!v) return 'validation.nameRequired';  // translation key
  ...
  return null;
}
```

Keys are resolved in JSX via `t()`:
```jsx
{nameErr && <div className="form-error active">{t(nameErr)}</div>}
```

This keeps validator functions pure (no dependency on `t`) while supporting full i18n.

## What is Fully Translated

Every user-facing string on the public site is now translatable:

- Navigation labels
- Hero text, tags, and CTA buttons
- Section headings
- All page titles and descriptions
- All skill card content (names, levels, details)
- All strength card content (titles, points)
- All project card and modal content (titles, descriptions, problems, solutions, lessons)
- Resource card descriptions
- Contact form labels, placeholders, validation errors, and character counter
- Footer copyright text
- 404 page text
- All aria-labels for accessibility
- UI action strings (view details, visit, close modal, etc.)

---

## What is NOT Translated (Intentionally)

- **Backoffice** — All English-only (see `backoffice.spec.md`)
- **Brand names** — LinkedIn, GitHub, Codeboxx, resource titles (Codeboxx Academy, Codecademy)
- **Technology names** — HTML, CSS, JavaScript, React, etc. (universal)
- **Personal name** — "Coach E.T @ Codeboxx" (copyright line)
- **Secret shortcut** — Cmd/Ctrl+Shift+K backoffice access (no user-facing text)
